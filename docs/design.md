# 寺廟安燈管理系統 設計文件（v4）

> 源自 claude.ai 看板 `temple-system-plan-v3.jsx`，2026-11-05 review 後定為 v4。本文只保留決定後的內容；v3 原文與 review 過程見 `docs/archive/design-v3-with-review.md`。

## 1. 系統概覽

### 系統定位

寺廟安燈管理系統，管理每年度信眾安燈作業。以「戶」為操作單位，支援多燈種登記、生辰記錄、安燈卡與頌經名冊列印。一年一次安燈週期，年度由系統設定手動切換。

### 核心功能

戶籍管理、信眾管理、燈種管理、年度安燈登記、收款與日結、安燈卡列印、頌經名冊列印、舊系統資料匯入、系統設定。

### 業務規則

- 以戶為單位操作
- 戶長名搜尋；電話或其他聯絡資料可記、非必填，也可用電話找戶
- 戶長可更換、可不安燈
- 信眾軟刪除
- 同人同燈同年唯一
- 同戶可多次來訪
- 當場收齊，紙本可事後補登
- 年度手動切換

### 範圍外

捐款收據、法會報名、信眾端網站或 LINE、多廟、線上付款、Tauri 與 Flutter。

### 使用者

廟方工作人員 1 至 2 人。操作場景為信眾到廟裡時，工作人員查詢該戶、勾選要安的燈、收款、列印安燈卡。年底產出頌經名冊供法會使用。

## 2. 技術架構

| 層 | 技術 | 說明 |
| --- | --- | --- |
| 後端 | Spring Boot 4、Java 25 | 純 REST API，Spring Data JPA，Flyway 管 schema |
| 資料庫 | PostgreSQL | DB 層不用 ENUM，用 VARCHAR 配 CHECK 與 JPA 字串列舉 |
| 前端 | React + Vite + TypeScript | build 產物放進 Spring Boot 的 `static/`，部署為單一 jar |
| 列印 | React 列印頁 + CSS print；PDF 由 Chromium 渲染同一頁 | 見第 8 節，待拍板 |
| 部署 | 寺廟區網內一台機器跑 jar，其他電腦開瀏覽器連 IP | 不做 Tauri、Flutter；單機安裝需求用 `jpackage` |

### 決策紀錄

- **為何前後端分離？** REST API 不綁定任何前端殼，之後要包桌面或手機版不會被堵死。
- **為何不用 Thymeleaf？** Server-side rendering 綁死網頁版。
- **為何取消 Tauri 與 Flutter？** 區網架構下 client 就是瀏覽器，Tauri 桌面版只多一個殼；Tauri 2 已能打包行動版，Flutter 沒有獨立存在的理由。
- **為何前端用 React？** 2026-11-05 決定。

### 開發順序

1. Phase 1：Spring Boot REST API + React 網頁版，核心功能完成。
2. Phase 2：舊系統資料匯入，開發完成後再處理；schema 已預留 `legacy_id`、`kind = IMPORT`、戶號 identity，屆時不需改表。
3. 之後視需求：批次列印、統計、Excel 匯出。

### DDL（PostgreSQL，Flyway `V1__init.sql` 底稿）

```sql
-- 資料庫時區固定台北，CURRENT_DATE 才會對；應用層仍應明確帶日期
ALTER DATABASE temple SET timezone = 'Asia/Taipei';

CREATE TABLE users (
  id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  username      VARCHAR(50)  NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  display_name  VARCHAR(50)  NOT NULL,
  role          VARCHAR(10)  NOT NULL CHECK (role IN ('ADMIN', 'STAFF')),
  is_active     BOOLEAN      NOT NULL DEFAULT TRUE,
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);

CREATE TABLE system_configs (
  config_key   VARCHAR(50)  PRIMARY KEY,
  config_value VARCHAR(255) NOT NULL,
  description  VARCHAR(255),
  updated_by   BIGINT       REFERENCES users(id),
  updated_at   TIMESTAMPTZ  NOT NULL DEFAULT now()
);
-- 初始：current_year=2027（西元）、temple_name、temple_address、
--       taisui_relations=值,沖,刑,害,破（各廟可刪減）、prayer_month=十二

CREATE TABLE households (
  id               BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  household_number INT    GENERATED BY DEFAULT AS IDENTITY UNIQUE,
  city             VARCHAR(10),
  district         VARCHAR(10),
  address          VARCHAR(200),
  phone            VARCHAR(20),
  contact_note     VARCHAR(100),
  notes            TEXT,
  legacy_id        INT UNIQUE,
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- city 縣市、district 鄉鎮市區，列印時連寫「新北市三重區」；address 為其後的街路門牌
-- phone、contact_note（LINE、代辦人等）皆選填；戶的聯絡資料代表全戶
CREATE INDEX ix_households_phone ON households (phone) WHERE phone IS NOT NULL;
-- 匯入舊戶號後：SELECT setval(pg_get_serial_sequence('households','household_number'), MAX(household_number))

CREATE TABLE members (
  id                  BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  household_id        BIGINT      NOT NULL REFERENCES households(id),
  name                VARCHAR(50) NOT NULL,
  gender              VARCHAR(1)  CHECK (gender IN ('M', 'F')),
  is_head             BOOLEAN     NOT NULL DEFAULT FALSE,
  sort_order          SMALLINT    NOT NULL DEFAULT 0,
  city                VARCHAR(10),
  district            VARCHAR(10),
  address             VARCHAR(200),
  phone               VARCHAR(20),
  birth_ganzhi        VARCHAR(2)
    CHECK (birth_ganzhi ~ '^[甲乙丙丁戊己庚辛壬癸][子丑寅卯辰巳午未申酉戌亥]$')
    CHECK (birth_ganzhi IS NULL OR
           (position(substr(birth_ganzhi, 1, 1) IN '甲乙丙丁戊己庚辛壬癸')
          - position(substr(birth_ganzhi, 2, 1) IN '子丑寅卯辰巳午未申酉戌亥')) % 2 = 0),
  birth_branch        VARCHAR(1)  GENERATED ALWAYS AS (substr(birth_ganzhi, 2, 1)) STORED,
  birth_month         SMALLINT    CHECK (birth_month BETWEEN 1 AND 12),
  birth_month_is_leap BOOLEAN     NOT NULL DEFAULT FALSE,
  birth_day           SMALLINT    CHECK (birth_day BETWEEN 1 AND 30),
  birth_hour_branch   VARCHAR(1)  CHECK (birth_hour_branch IN ('子','丑','寅','卯','辰','巳','午','未','申','酉','戌','亥')),
  deleted_at          TIMESTAMPTZ,
  delete_reason       VARCHAR(100),
  legacy_id           INT UNIQUE,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (NOT birth_month_is_leap OR birth_month IS NOT NULL)
);
-- 生辰四欄 NULL 一律顯示為「吉」；第二條 CHECK 擋掉干支奇偶不合的 60 甲子以外組合
-- birth_branch 供太歲查詢；city/district/address 為 NULL 時列印取戶的值
CREATE UNIQUE INDEX ux_members_one_head_per_household
  ON members (household_id) WHERE is_head AND deleted_at IS NULL;
CREATE INDEX ix_members_household ON members (household_id);
CREATE INDEX ix_members_name      ON members (name);
CREATE INDEX ix_members_phone     ON members (phone) WHERE phone IS NOT NULL;

CREATE TABLE light_types (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  category    VARCHAR(10) NOT NULL CHECK (category IN ('GENERAL', 'BAGUA')),
  name        VARCHAR(50) NOT NULL UNIQUE,
  short_name  VARCHAR(20) NOT NULL,
  price       INT         NOT NULL CHECK (price >= 0),
  is_taisui   BOOLEAN     NOT NULL DEFAULT FALSE,
  sort_order  INT         NOT NULL DEFAULT 0,
  is_active   BOOLEAN     NOT NULL DEFAULT TRUE,
  legacy_code VARCHAR(20) UNIQUE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- short_name 印在安燈卡，省略「燈」字：光明、文昌、太歲
-- is_taisui 只標記「哪一種燈是太歲燈」供犯太歲提示，限標一種；
-- 同人同燈同年唯一由 annual_light_records 的 UNIQUE 保證，26 種燈一體適用
CREATE UNIQUE INDEX ux_light_types_single_taisui ON light_types (is_taisui) WHERE is_taisui;

CREATE TABLE light_orders (
  id                BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind              VARCHAR(10) NOT NULL DEFAULT 'COUNTER' CHECK (kind IN ('COUNTER', 'CORRECTION', 'IMPORT')),
  status            VARCHAR(10) NOT NULL DEFAULT 'ACTIVE'  CHECK (status IN ('ACTIVE', 'VOIDED')),
  year              INT         NOT NULL CHECK (year BETWEEN 1990 AND 2100),
  household_id      BIGINT      NOT NULL REFERENCES households(id),
  registered_on     DATE        NOT NULL DEFAULT CURRENT_DATE,
  posted_on         DATE        NOT NULL DEFAULT CURRENT_DATE,
  total_due         INT         NOT NULL,
  corrects_order_id BIGINT      REFERENCES light_orders(id),
  note              VARCHAR(200),
  created_by        BIGINT      REFERENCES users(id),
  created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
  voided_by         BIGINT      REFERENCES users(id),
  voided_at         TIMESTAMPTZ,
  void_reason       VARCHAR(200),
  CHECK ((kind = 'CORRECTION') = (corrects_order_id IS NOT NULL)),
  CHECK ((status = 'VOIDED') = (voided_at IS NOT NULL))
);
-- year 一律西元，CHECK 順便擋掉誤填的民國年
-- registered_on 交易日（補登填紙本日期）；posted_on 入帳日，系統給，不可改
-- total_due = SUM(ADD unit_price) − SUM(REMOVE unit_price)，可為負（應退）
-- 更正單的明細可跨戶，household_id 記主要服務的戶
CREATE INDEX ix_light_orders_household_year ON light_orders (household_id, year);
CREATE INDEX ix_light_orders_posted_on      ON light_orders (posted_on);

CREATE TABLE light_order_items (
  id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  order_id        BIGINT     NOT NULL REFERENCES light_orders(id),
  member_id       BIGINT     NOT NULL REFERENCES members(id),
  light_type_id   BIGINT     NOT NULL REFERENCES light_types(id),
  action          VARCHAR(6) NOT NULL CHECK (action IN ('ADD', 'REMOVE')),
  unit_price      INT        NOT NULL CHECK (unit_price >= 0),
  override_reason VARCHAR(100),
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- unit_price 預設燈種現價；ADMIN 可覆寫並必填 override_reason
CREATE INDEX ix_items_order        ON light_order_items (order_id);
CREATE INDEX ix_items_member_light ON light_order_items (member_id, light_type_id);

CREATE TABLE payments (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  order_id    BIGINT      NOT NULL REFERENCES light_orders(id),
  kind        VARCHAR(10) NOT NULL DEFAULT 'CASH' CHECK (kind IN ('CASH', 'FORFEIT', 'IMPORT')),
  amount      INT         NOT NULL CHECK (amount <> 0),
  received_on DATE        NOT NULL DEFAULT CURRENT_DATE,
  posted_on   DATE        NOT NULL DEFAULT CURRENT_DATE,
  received_by BIGINT      REFERENCES users(id),
  note        VARCHAR(200),
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (kind = 'IMPORT' OR received_by IS NOT NULL)
);
-- amount 帶正負。CASH：正為收款、負為退款，計入日結。
-- FORFEIT：放棄退款（轉功德金），不動現金，作廢沖正時以正數反向。IMPORT：舊資料的歷史收款，不計入日結。
-- 結清條件：total_due − SUM(amount) = 0；不為 0 的單列入「差額待處理」
CREATE INDEX ix_payments_order     ON payments (order_id);
CREATE INDEX ix_payments_posted_on ON payments (posted_on);

CREATE TABLE daily_closings (
  closing_date DATE   PRIMARY KEY,
  system_cash  INT    NOT NULL,
  counted_cash INT    NOT NULL,
  difference   INT    GENERATED ALWAYS AS (counted_cash - system_cash) STORED,
  closed_by    BIGINT NOT NULL REFERENCES users(id),
  closed_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  note         VARCHAR(200)
);
-- system_cash = SUM(payments.amount) WHERE kind = 'CASH' AND posted_on = closing_date
-- difference 即長短款。關帳日 = MAX(closing_date)，posted_on ≤ 關帳日的單與收款不可作廢、不可新增

CREATE FUNCTION forbid_change() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION '% is append-only', TG_TABLE_NAME;
END $$;
CREATE TRIGGER trg_items_immutable
  BEFORE UPDATE OR DELETE ON light_order_items
  FOR EACH ROW EXECUTE FUNCTION forbid_change();
CREATE TRIGGER trg_payments_immutable
  BEFORE UPDATE OR DELETE ON payments
  FOR EACH ROW EXECUTE FUNCTION forbid_change();

CREATE TABLE annual_light_records (
  id                 BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  year               INT     NOT NULL CHECK (year BETWEEN 1990 AND 2100),
  member_id          BIGINT  NOT NULL REFERENCES members(id),
  light_type_id      BIGINT  NOT NULL REFERENCES light_types(id),
  household_id       BIGINT  NOT NULL REFERENCES households(id),
  unit_price         INT     NOT NULL,
  is_active          BOOLEAN NOT NULL DEFAULT TRUE,
  last_order_item_id BIGINT  REFERENCES light_order_items(id),
  created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (member_id, light_type_id, year)
);
CREATE INDEX ix_alr_household_year    ON annual_light_records (household_id, year);
CREATE INDEX ix_alr_year_light_active ON annual_light_records (year, light_type_id) WHERE is_active;

CREATE TABLE audit_logs (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  table_name  VARCHAR(40) NOT NULL,
  row_id      BIGINT      NOT NULL,
  action      VARCHAR(10) NOT NULL CHECK (action IN ('INSERT', 'UPDATE', 'DELETE')),
  before_data JSONB,
  after_data  JSONB,
  changed_by  BIGINT      REFERENCES users(id),
  changed_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
-- 由 service 寫入，涵蓋 members、households、light_types、system_configs 的異動；
-- 單據、明細、收款本身只增不改，有自己的 created_by / voided_by，不另記
CREATE INDEX ix_audit_logs_row ON audit_logs (table_name, row_id);
CREATE TRIGGER trg_audit_logs_immutable
  BEFORE UPDATE OR DELETE ON audit_logs
  FOR EACH ROW EXECUTE FUNCTION forbid_change();
```

### 資料規則

- **聯絡資料**：戶與成員各有選填的 `phone`，戶另有 `contact_note`。搜尋戶時姓名與電話都可用，同名時靠電話分辨。
- **戶長**：一戶最多一位未刪除的戶長，由 partial unique index 保證。刪除戶長時介面要求指定新戶長，或允許暫無戶長。
- **戶的刪除**：沒有成員也沒有單據的戶可硬刪；有歷史的戶不刪，由成員狀態呈現。
- **移戶**：成員改 `household_id` 時，當年 `is_active` 的狀態表紀錄一併改到新戶，歷年不動。
- **重複建檔**：第一版不做合併介面，用 SQL 處理。
- **狀態表與明細**：每寫一筆 item 就 upsert 對應的 `annual_light_records`，`last_order_item_id` 指向該 item。狀態表可由明細整個重算。
- **顯示民國**：資料庫年份與日期一律西元，畫面與列印顯示民國（年度「民國 116 年」、日期「116/01/15」），轉換在前端。
- **地址三段**：`city` 縣市、`district` 鄉鎮市區、`address` 街路門牌。輸入用縣市與鄉鎮市區兩層下拉；安燈卡的「區」列印 `city` + `district`。
- **刪除成員**：介面用語是「刪除成員」，資料面仍是軟刪除（記 `deleted_at` 與原因），不硬刪。成員被刪除時不自動 REMOVE，當年狀態表紀錄保留，名冊照印；矩陣編輯與戶內成員清單才排除已刪除成員。
- **同人同燈同年唯一**：`annual_light_records` 的 UNIQUE 對 26 種燈一體適用，光明、文昌、太歲各只能一筆，八卦轉運斗每一型各一筆、不同型可多選。沒有任何燈種允許同一人同年安兩盞以上，所以狀態表不帶數量。
- **稽核日誌**：成員、戶、燈種、設定的新增、修改、軟刪除由 service 寫入 `audit_logs`，存修改前後整列 JSON，查「這個生辰是誰、何時改的」。
- **太歲**：年度地支由 `current_year` 算出（`(year − 4) mod 12` 對應子丑寅卯），成員地支取 `birth_branch`，值、沖、刑、害、破由程式算，哪些算犯太歲看 `system_configs.taisui_relations`。`birth_ganzhi` 為 NULL 者跳過。
- **匯入**：舊資料每戶每年產生一張 `kind = IMPORT` 的單與明細，`registered_on` 填歷史日期，收款以 `kind = IMPORT` 的 payment 結清、不計入日結，再由同一套邏輯長出狀態表。
- **時區**：資料庫設 `Asia/Taipei`，應用層所有日期欄位仍明確帶值，不依賴 DB 預設。

## 4. 生辰設計

| 欄位 | 內容 | 「吉」 |
| --- | --- | --- |
| `birth_ganzhi` | 天干地支年，如「辛亥」，共 60 種，操作人員直接打字 | NULL |
| `birth_month` | 農曆月 1 至 12 | NULL |
| `birth_month_is_leap` | 是否閏月 | FALSE |
| `birth_day` | 農曆日 1 至 30 | NULL |
| `birth_hour_branch` | 地支時辰一個字 | NULL |

名冊列印組合：`{年}年 {閏?}{月}月 {日}日 {時}時 生`，NULL 顯示「吉」。範例：`辛亥年 1月 9日 吉時生`、`辛巳年 9月 10日 辰時生`。安燈卡不印生辰。

## 6. 單據與金額（銀行切法）

### 兩本帳

- `light_order_items` 只記登記變動，`payments` 只記錢。
- `total_due = SUM(ADD unit_price) − SUM(REMOVE unit_price)`，可為負。
- 結清條件 `total_due − SUM(payments.amount) = 0`；不為 0 的單列在「差額待處理」。
- 日結看入帳日 `posted_on`，收入報表看交易日 `registered_on`、`received_on`。

### 流程

| 流程 | 條件 | 做法 | 權限 |
| --- | --- | --- | --- |
| 櫃台單 | 平常 | 存檔時寫單、明細、更新狀態表，並自動產生一筆 CASH 收款等於 `total_due`；為負時產生 FORFEIT 結清，不退現 | STAFF |
| 補登 | 紙本事後鍵入 | 同櫃台單，但 `registered_on` 與 `received_on` 逐筆填紙本日期；入帳日仍是今天 | STAFF |
| 沖正（作廢） | 該單 `posted_on` 尚未日結 | `status = VOIDED`，寫反向明細讓狀態表復原，已收現金以 CASH 負數記退款 | ADMIN |
| 調整（更正單） | 原單已日結 | 開 `kind = CORRECTION` 引用原單，明細 REMOVE 加 ADD，可跨戶；差額以今天的 CASH 或 FORFEIT 結清，溢收短收先留差額待處理 | ADMIN |
| 日結 | 每日收班 | 輸入實點現金，系統算當日 CASH 合計與長短款；日結後該日凍結 | STAFF |
| 關帳 | 安燈季結束 | 把最後一天日結，關帳日即最大的 `closing_date` | ADMIN |

### 其他規則

- 事後發現的長短款以更正單的收款對銷，不改原日結。
- `unit_price` 預設燈種現價，ADMIN 可改並必填 `override_reason`。
- 匯入單不可作廢。
- Rebuild 工具核對三件事：`total_due` 對明細、狀態表對明細、`system_cash` 對收款。

## 7. 操作流程

### 年度安燈櫃台流程

1. **搜尋戶長**：輸入戶長姓名，找到該戶。新戶先建戶籍與成員。
2. **確認成員**：顯示未刪除成員，可新增、編輯、軟刪除、更換戶長。犯太歲的成員標示出來。
3. **開單**：系統開一張 `kind = COUNTER` 的單，年度從 `current_year` 帶入。
4. **勾選燈種**：成員 × 燈種矩陣，讀狀態表顯示已安的燈，可新增勾選或取消勾選。
5. **確認收款**：畫面列三行：新增幾盞多少元、取消幾盞折抵多少、應收多少。收現金。
6. **完成**：同一 transaction 寫單、明細、狀態表、收款。可立即列印安燈卡。

### 年度切換

操作人員在設定頁修改 `current_year`。效果：安燈操作自動帶入新年度、矩陣顯示新年度一開始全空、歷史年度完整保留、不影響任何既有資料。

### 技術方案（建議，待拍板）

- 安燈卡與名冊各做成獨立的 React 列印頁，字型用 `@font-face` 從 jar 載入 Noto Sans TC，`@page` 定紙張與邊界，`break-before` 依戶分頁。
- 因為 Windows 與 Mac 都要印且要歸檔，伺服器端用 Playwright Java 以 Chromium 開同一個列印頁產 PDF，`preferCSSPageSize` 開啟，回傳並存入年度歸檔目錄。櫃台用瀏覽器開 PDF，列印縮放選「實際大小」。

## 10. 決策紀錄與待決

### 已決定（2026-11-05）

- 前端 React + Vite + TypeScript；只做 Web 版，取消 Tauri 與 Flutter。
- 電話或其他聯絡資料可記、非必填（2026-11-06）。
- 2026-11-06 原型回饋：配色用現代明亮色系；介面用語「刪除成員」；區含縣市與鄉鎮市區，欄位拆 `city` 與 `district`；資料庫西元、顯示民國；矩陣標頭不顯示價格、需要時再看；格子點一下勾選、再點一下移除；八卦轉運斗不排 23 欄，改在每位成員列下直接排出 23 型按鈕，點選即生效，不需展開。
- 2026-11-06 確認的前提：只有一間廟；不開立收據，安燈卡是唯一給信眾的紙；價格全廟統一，特殊情況走 ADMIN 改價；沒有燈種允許同一人同年安兩盞以上；日結以鍵入系統當天為準，補登的現金與紙本一起交；信眾端不接觸系統；舊系統歷年安燈紀錄全部搬入；區網不需要 HTTPS 但要登入。
- 後端 Spring Boot 4、Java 25；資料庫 PostgreSQL；DB 層不用 ENUM。
- 舊系統為 MariaDB，可匯出 SQL dump；資料匯入在開發完成後處理（2026-11-05），戶號沿用。
- 金額採銀行切法：兩本帳、交易日與入帳日分開、日結前沖正、日結後調整、日結記長短款、作廢與更正限 ADMIN。REMOVE 預設不退費，以 FORFEIT 結清。
- 八卦轉運斗可多選；已安燈成員被軟刪除時當年紀錄保留到年底；不存年齡。
- 年份一律西元；戶號用 PostgreSQL identity；戶長只留 `members.is_head`；生辰「吉」一律 NULL；太歲提示依 `birth_branch` 計算。
- 安燈卡燈名省略「燈」字，`light_types` 加 `short_name`。
- 加 `audit_logs` 記成員、戶、燈種、設定的異動歷史。
- 姓名搜尋用 `LIKE`，不加 `pg_trgm`。
